# OpenSTA Demo (M2.5) — Netlist + Liberty + SDC → Timing Report

This directory demonstrates the fundamental STA chain of the platform:

```
design.v (TOY counter, no PDK claim)
   ↓  Yosys mapped synthesis (dfflibmap + abc -liberty)
mapped.v  (real Nangate45 standard cells: DFFR_X1, NAND2/3_X1, XNOR2_X1, XOR2_X1)
   ↓  OpenSTA 3.1.0 (pinned container) + demo Liberty + SDC
timing report (real slack / worst slack / TNS)
```

## Files

| File | Purpose |
|---|---|
| `design.v` | TOY 4-bit counter (copy of `examples/rtl/simple_counter.v`) — not a real chip |
| `synth_mapped.ys` | Yosys mapped synthesis: `dfflibmap` + `abc -liberty` map onto demo library cells |
| `timing.sdc` | Minimal constraints: 0.5 ns clock on `clk`, input delay on `rst_n`, output delay on `count` |
| `sta.tcl` | OpenSTA script: `read_liberty` → `read_verilog` → `link_design` → `read_sdc` → reports |
| `demo_nangate45_typ.lib` | **fetched, not committed** — extracted from the pinned `aemp-eda-opensta` image (`/OpenSTA/test/nangate45/Nangate45_typ.lib`, Nangate Inc. copyright) |
| `mapped.v` | generated by the demo synthesis |

## Why the M2.4 generic netlist cannot be used

The M2.4 `synth` output contains Yosys-internal cells rendered behaviorally
(`assign`/`always`) — **zero standard-cell instances**. OpenSTA needs a
Liberty timing model for every cell it links; with no cells (or unknown
cells) there is nothing to time and OpenSTA rejects the netlist
(observed: `Error: 171 inputs/synthesized.v line 11, syntax error`).
Mapped synthesis against a Liberty library is therefore a prerequisite.

## Run it

```bash
python scripts/check_eda_env.py              # docker + both images
aemp run --rtl examples/rtl/simple_counter.v --top simple_counter   # generic (for contrast)
aemp sta --netlist <mapped.v> --liberty <demo.lib> --sdc examples/sta/timing.sdc --top simple_counter
```

Or use `scripts/demo_yosys_driver.py` + `aemp sta` as in the M2.5 report.

## Reading the result

A successful run archives the tool stdout as `artifacts/timing.rpt`
(OpenSTA 3.1.0 has no `redirect` command; reports go to stdout). Real
numbers from the demo (0.5 ns clock):

```
data path  : DFFR_X1 → NAND3_X1 → XNOR2_X1 → DFFR_X1
slack (MET): 0.29
worst slack max 0.29
tns max 0.00
```

**`sta` exiting 0 says nothing about timing quality.** Even with
`WNS = -1.2` OpenSTA exits 0 — a timing verdict is the QA engine's job
(M5), which does not exist yet. The run records execution facts only.
