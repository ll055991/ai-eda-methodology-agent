# 1. M6.3 唯一目标

本阶段目标：

> **把 StubAgentRuntime 替换为真正可以调用 LLM 的 LLMAgentRuntime，同时建立可替换的 Model Provider 抽象。**

最终：

```

 ↓

 ↓
ChatService
 ↓
AgentRuntime
 ↓

 ↓
```

必须做到：

```

ChatService 不知道具体 Provider
AgentRuntime 不知道 HTTP API 细节
Platform Backend 不知道 LLM
PlatformClient 不参与 LLM 调用
```

# 3. M6.3 为什么不能直接做 Tool Calling

不要实现：

```
User
 ↓
LLM
 ↓
Tool Call
 ↓
PlatformClient
```

这一部分留到：

```
M6.4
```

M6.3 只验证：

```
User
 ↓
Agent
 ↓
LLM
 ↓
Text Response
```

原因：

如果 M6.3 同时加入 Tool Calling，一旦出现问题无法判断：

```
LLM Provider 问题
还是
Tool Calling 问题
还是
Platform API 问题
```

当前阶段必须保持单一变量。

# 5. Provider 抽象

建议新增：

```
agent-backend/src/agent_backend/llm/
├── __init__.py
├── models.py
├── base.py
├── errors.py
├── openai_compatible.py
└── factory.py
```

核心接口：

```
class ModelProvider(Protocol):
    def chat(
        self,
        messages: list[ChatMessage],
        *,
        temperature: float | None = None,
        max_tokens: int | None = None,
    ) -> ModelResponse:
        ...
```

如果当前代码结构更适合，可以调整。

但必须保证：

> AgentRuntime 依赖 ModelProvider 抽象，而不是具体 OpenAI/DeepSeek/其他 SDK。

# 6. 为什么叫 ModelProvider

不要设计成：

```
class DeepSeekModel:
```

然后：

```
Agent → DeepSeekModel
```

应该：

```
Agent
 ↓
ModelProvider
 ↓
OpenAICompatibleProvider
 ↓
实际 API
```

未来可以替换：

```
OpenAI
DeepSeek
Qwen
Claude
本地 vLLM
Ollama
其他 OpenAI-compatible endpoint
```

而不用修改 AgentRuntime。

# 7. M6.3 第一版只实现 OpenAI-Compatible Provider

只实现：

```
OpenAICompatibleProvider
```

不要同时实现：

```
OpenAIProvider
DeepSeekProvider
QwenProvider
AnthropicProvider
OllamaProvider
```

原因：

很多现代模型 API 都可以通过 OpenAI-compatible API 接入。

例如：

```
base_url
api_key
model
```

形成统一：

```
POST {base_url}/chat/completions
```

但：

> 不要假设所有 provider 永远完全兼容。

Provider 层就是未来处理差异的边界。

# 8. 不要强依赖具体厂商 SDK

优先使用：

```
httpx
```

直接调用 OpenAI-compatible HTTP API。

M6.3 不需要：

```
openai SDK
langchain
langgraph
deepagents
```

原因：

当前目标是学习并建立：

```
Agent Runtime
      ↓
Provider Abstraction
      ↓
HTTP Model API
```

而不是绑定一个 Agent Framework。

# 9. Model Request

建议定义：

```
@dataclass(frozen=True)
class ChatMessage:
    role: Literal["system", "user", "assistant"]
    content: str
```

然后：

```
@dataclass(frozen=True)
class ModelRequest:
    model: str
    messages: tuple[ChatMessage, ...]
    temperature: float | None = None
    max_tokens: int | None = None
```

不要加入：

```
tools
tool_choice
response_format
reasoning
parallel_tool_calls
```

这些全部属于后续能力。

# 10. Model Response

建议最小化：

```
@dataclass(frozen=True)
class ModelResponse:
    content: str
    model: str | None
    finish_reason: str | None
    usage: ModelUsage | None
    provider: str
    request_id: str | None
```

Usage：

```
@dataclass(frozen=True)
class ModelUsage:
    prompt_tokens: int | None
    completion_tokens: int | None
    total_tokens: int | None
```

注意：

> Provider 返回什么字段不代表所有模型都一定提供。

所以：

```
missing usage
missing model
missing finish_reason
```

必须允许为：

```
None
```

不要伪造。

# 25. Timeout

Provider 必须设置 timeout。

例如：

```
AEMP_LLM_TIMEOUT_S=60
```

禁止：

```
timeout=None
```

无限等待。

异常映射：

```
httpx.TimeoutException
        ↓
LLMTimeoutError
```

# 26. Response Validation

OpenAI-compatible response 至少验证：

```
choices
choices[0]
message
message.content
```

如果结构错误：

```
LLMResponseError
```

不要：

```
response.json()["choices"][0]["message"]["content"]
```

直接假设永远存在。

# 27. Empty Response

如果：

```
HTTP 200
choices=[]
```

或者：

```
content=""
```

需要根据当前 API 语义进行明确处理。

不要自动返回：

```
""
```

作为成功回答。

建议：

```
LLMResponseError
```

除非当前 provider 明确允许空内容。

# 28. Usage 解析

如果 Provider 返回：

```
{
  "usage": {
    "prompt_tokens": 100,
    "completion_tokens": 30,
    "total_tokens": 130
  }
}
```

解析。

如果不存在：

```
usage = None
```

不能：

```
prompt_tokens = 0
```

因为：

```
Unknown
≠
0
```

这与 M4/M5 的数据语义保持一致。
