# 二、本阶段目标

实现：

# M7.1 Skill System

目标：

让 Agent 从：

```
System Prompt
+
Tools
```

升级为：

```
System Prompt
+
Skill Discovery
+
按需 Skill Loading
+
Tools
```

核心理念：

> Skill 是 Agent 的领域能力/工作方法封装，不是 Tool。

Skill 不直接执行 EDA。

Skill 不能绕过 ToolGateway。

Skill 不能直接访问：

- subprocess
- shell
- Docker
- SQLite
- 文件系统中的任意路径
- Platform API
- 网络

Skill 的职责是：

```
告诉 Agent：

什么时候使用这个能力
需要什么知识
应该按照什么步骤处理问题
有哪些注意事项
应该调用哪些 Tool
如何解释结果
```

# 三、先理解 Skill 与 Tool 的区别

必须在代码和文档中明确：

```
Skill
=
Knowledge + Procedure + Guidance

Tool
=
Executable Capability
```

例如：

```
Skill: timing-analysis

告诉 Agent：

1. 什么时候需要 STA
2. 需要什么输入
3. 应该运行什么 Flow
4. 如何读取 WNS/TNS
5. WNS < 0 如何判断
6. 常见失败原因是什么
7. 什么时候需要进一步诊断
```

而：

```
Tool: run_flow
```

负责真正执行 Flow。

不要让 Skill 变成：

```
Skill → subprocess
```

也不要让 Skill 变成：

```
Skill → Python function → Docker
```

# 五、Skill Markdown 格式

定义一个明确、稳定、可扩展的 SKILL.md 格式。

建议：

```
---
name: timing-analysis
description: Analyze STA timing results and identify timing violations.
version: "1.0"
tags:
  - sta
  - timing
  - methodology
---

# Timing Analysis

## When to use

Use this skill when:
- user asks about timing
- STA has been executed
- WNS/TNS need interpretation
- timing violations need analysis

## Inputs

Expected information:
- run_id
- STA result
- timing metrics

## Procedure

1. Inspect run status.
2. Retrieve artifacts.
3. Run QA when required.
4. Inspect WNS/TNS.
5. Determine whether timing passes.
6. If failed, identify possible causes.
7. Recommend next action.

## Tool guidance

Preferred tools:
- get_run
- get_artifacts
- run_qa

Do not directly execute shell commands.

## Interpretation

- WNS >= 0: timing constraint is not violated.
- WNS < 0: setup timing violation exists.
- TNS < 0: aggregate negative slack exists.

## Limitations

This skill only interprets available evidence.
Do not invent missing metrics.
```

注意：

这些内容只是示例。

Coding Agent 必须结合项目实际 schema / API / parser / QA 结果设计最终格式。

# 八、Progressive Disclosure

这是 M7.1 的重点。

实现：

```
Level 1
Skill Catalog
    ↓
Level 2
SKILL.md
    ↓
Level 3
references/*
```

原则：

```
不需要
→ 不加载

需要某 Skill
→ 加载 SKILL.md

需要详细资料
→ 加载 references
```

不要把所有 Skill Markdown 全部拼到 system prompt。

# 十五、安全边界

必须保持：

```
Agent
 ↓
Skill
 ↓
ToolGateway
 ↓
Platform
```

而不是：

```
Agent
 ↓
Skill
 ↓
subprocess
```

Skill 内容本身也属于：

> Untrusted / semi-trusted configuration

因此：

- 不执行 Markdown 中的代码
- 不执行 Skill 中的 shell
- 不动态 import Skill
- 不允许 Skill 修改 Tool Registry
- 不允许 Skill 绕过 PolicyEngine
- 不允许 Skill 绕过 HITL

尤其：

```

```

仍然是：

```
HIGH RISK
 ↓
PolicyEngine
 ↓
HITL
```

Skill 不能让它自动执行。
