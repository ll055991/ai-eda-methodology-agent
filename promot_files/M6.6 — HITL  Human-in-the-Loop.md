# 一、M6.6 的核心目标

M6.5：

```
LLM
 ↓
Tool Call
 ↓
Tool Node
 ↓
Platform
```

M6.6：

```
LLM
 ↓
Tool Call
 ↓
Policy
 ↓
需要审批？
 ├── No ─────────→ Tool
 │
 └── Yes
       ↓
   INTERRUPT
       ↓
   Checkpoint
       ↓
   等待人工
       ↓
   Approve / Reject
       ↓
   Resume
       ↓
   Tool
```

例如：

```
用户：
运行 rtl_to_sta Flow。

LLM：
tool_call = run_flow

Policy：
run_flow = HIGH_RISK
需要人工审批

Agent：
等待审批
approval_id = approval_xxx

人工：
Approve

Agent Resume：
ToolGateway
 ↓
run_flow
 ↓
Platform
```

如果：

```
人工 Reject
```

则：

```
Tool 不执行
 ↓
Agent 收到 rejection
 ↓
最终回答
```


其中：

```
run_flow = HIGH
```

其他：

```
get_run       = LOW
run_qa        = LOW
```

# 五、Policy 层

新增：

```
agent-backend/src/agent_backend/policy/
```

建议：

```
policy/
├── __init__.py
├── models.py
├── rules.py
└── engine.py
```

具体结构可以根据当前代码调整。

核心模型：

```
@dataclass(frozen=True)
class ToolPolicy:
    tool_name: str
    risk_level: Literal["low", "high"]
    approval_required: bool
```

Policy Engine：

```
class PolicyEngine:
    def evaluate(
        self,
        tool_call: ToolCall,

        ...
```

# 六、PolicyDecision

至少需要表达：

```
@dataclass(frozen=True)
class PolicyDecision:
    tool_name: str
    risk_level: str
    approval_required: bool
    reason: str
```

例如：

```
run_flow
 ↓
risk_level = high
approval_required = true
reason = "Executing an EDA flow may modify run state and consume compute resources."
```

# 七、不要让 LLM 决定是否需要审批

非常重要。

不能：

```
LLM：
这是安全操作，所以不需要审批。
```

然后直接执行。

审批判断必须在代码中：

```
Tool Call
 ↓
PolicyEngine
 ↓
approval_required
```

即：

```
LLM = intent
Policy = authorization decision
```

LLM 不拥有审批权限。

# 八、Policy 应该位于 Tool Execution 前

正确：

```
Agent Node
 ↓
Tool Call
 ↓
Policy
 ↓
Approval?
 ├── no → ToolGateway
 └── yes → interrupt
```

错误：

```
Agent Node
 ↓
ToolGateway
 ↓
Platform
 ↓
Policy
```

因为如果已经进入 ToolGateway / Platform：

**可能已经产生实际副作用。**

# 十一、LangGraph Interrupt

这是 M6.6 最核心的技术点。

在需要审批的 Tool 执行路径：

```
Tool Call
 ↓
Policy
 ↓
interrupt(...)
```

使用 LangGraph 当前版本对应的官方 interrupt 机制。

不要自己：

```
while waiting:
    sleep()
```

不要：

```
input()
```

不要：

```
threading.Event()
```

必须使用：

```
LangGraph interrupt
+
Checkpointer
+
Resume
```

# 十二、为什么必须使用 Checkpointer

M6.5：

```
graph.invoke(...)
```

请求结束后状态不持久化。

M6.6：

```
graph.invoke(...)
 ↓
interrupt
 ↓
请求结束
```

之后用户才会：

```
Approve
```

因此必须能够：

```
恢复之前的 Graph State
```

所以：

```
Checkpointer
```

是 M6.6 的必要组成部分。

# 十三、Thread ID

使用稳定的：

```
thread_id
```

将一次 Agent Execution 与 Checkpoint 关联。

优先复用当前：

```
session_id
```

如果当前架构无法直接使用 session_id：

增加明确的：

```
thread_id
```

但不要引入第二套随机状态标识体系。

原则：

```
HTTP Request
 ↓
session/thread identity
 ↓
LangGraph checkpoint
```

# 十四、Checkpointer 实现

M6.6 可以使用：

```
MemorySaver
```

或当前 LangGraph 1.x 对应的内存 Checkpointer 实现。

但必须明确：

> 当前版本只保证单进程生命周期内可恢复。

不要声称：

```
production durable persistence
```

因为：

```
Agent process restart
 ↓
Memory Checkpointer
 ↓
checkpoint lost
```

这是已知限制。

# 十五、不要引入 Redis / PostgreSQL

本阶段：

```
No Redis
No PostgreSQL
No external checkpoint database
```

先使用：

```
in-memory checkpointer
```

原因：

M6.6 的目标是理解：

```
interrupt
checkpoint
resume
```

持久化 Checkpointer 可以未来作为独立阶段。

# 十六、Graph 结构变化

M6.5：

```
START
 ↓
agent
 ↓
should_continue
 ├── END
 └── tools
       ↓
      agent
```

M6.6：

不要把 Policy/Approval 做成一个复杂 Graph Node。

建议：

```
START
 ↓
agent
 ↓
should_continue
 ├──────────────→ END
 │
 └──────────────→ tools
                     │
                     ▼
               policy_check
                     │
              ┌──────┴──────┐
              │             │
          no approval    approval
              │             │
              ▼             ▼
        ToolGateway      interrupt
                            │
                       resume
                            │
                            ▼
                       ToolGateway
                            │
                            ▼
                          agent
```

具体实现可以将 Policy 放在 Tool Node 内部的清晰函数中，但：

**审批判断必须发生在 ToolGateway.execute() 之前。**

# 十七、推荐的 Tool Node 流程

```
for tool_call in tool_calls:

    decision = policy.evaluate(tool_call)

    if decision.approval_required:

        approval = create_approval(...)

        interrupt({
            "type": "tool_approval",
            "approval_id": approval.approval_id,
            "tool_name": tool_call.name,
            "reason": decision.reason,
        })

        # resume 后继续

    result = gateway.execute(tool_call)
```

注意：

**不要把 Approval 做成 ToolGateway 的责任。**

ToolGateway 的职责仍然是：

```
Tool existence
+
Schema validation
+
Tool execution
```

Policy 是 Agent orchestration layer。

# 十八、Approve / Reject

Resume 时必须携带：

```
approval_id
decision
```

例如：

```
{
  "approval_id": "approval_123",
  "decision": "approved"
}
```

或者：

```
{
  "approval_id": "approval_123",
  "decision": "rejected",
  "reason": "Not authorized for this run."
}
```

# 十九、Reject 的语义

Reject：

```
Tool 不执行。
```

然后生成 Tool Result：

```
{
  "status": "error",
  "error_code": "APPROVAL_REJECTED",
  "error_message": "Human approval was rejected."
}
```

然后返回 Agent Node。

Agent 可以：

```
解释：
该 Flow 未获得人工批准，因此没有执行。
```

不要让 Reject 变成：

```
Agent failed
```

如果整个 Agent 仍然可以正常回答：

```
status = completed
```

这是：

> Tool rejected ≠ Agent crashed。

# 二十、Approve 的语义

Approve：

```
Resume
 ↓
重新进入 Tool execution
```

但是：

**不能重新走 LLM 决策后再问一次审批。**

应该恢复原来的：

```
tool_call
```

继续执行。

即：

```
LLM
 ↓
tool_call
 ↓
Policy
 ↓
INTERRUPT
 ↓
APPROVE
 ↓
原 tool_call
 ↓
ToolGateway
```

而不是：

```
APPROVE
 ↓
LLM
 ↓
重新生成一个 Tool Call
```

# 二十一、防止 Approval Bypass

必须测试：

```
High-risk Tool
 ↓
必须经过 Policy
 ↓
必须 interrupt
```

任何路径都不能：

```
LLM
 ↓
直接 ToolGateway
```

尤其不能：

```
tool_call
 ↓
某个 helper
 ↓
ToolGateway
```

绕过 Policy。


可以使用。


设计成长期权限 Token。

不要：

```

```

否则语义容易混乱。

```

```


# 二十五、Approval Response

当 Agent 被 interrupt 时：

HTTP 不应该假装：

```
completed
```

应该：

```
{
  "message": "Human approval required.",
  "status": "interrupted",
  "session_id": "...",
  "run_id": null,
  "approval_required": true,
  "approval_id": "approval_xxx"
}
```

如果当前 Agent API Schema 没有：

```
status = interrupted
```

则进行最小 Contract 扩展。

不要偷偷把：

```
approval_required=true
status=completed
```

混在一起。

# 二十六、状态语义

M6.6 后 Agent 状态至少：

```

completed
failed

```

其中：

```

```

表示：

> Agent 当前不是失败，而是在等待外部审批。

例如：

```
LLM → Tool → Approval
```

此时：

```
Agent = interrupted
```

而不是：

```
Agent = failed
```
